# Графики: данные и спецификации

Все графики строятся кодом внутри [`poster/poster.html`](../poster/poster.html) в теге `<script>` внизу файла. Данные лежат прямо в коде — правишь массив, график перестраивается сам.

## На постере сейчас

### График эвакуации (блок 04)

Ступенчатая линия, пять точек. Показывает, что событие обгоняло реакцию.

```js
var P = [
  {h:0.05, v:155 },  // 28 марта 22:03 — момент обращения акима
  {h:5,    v:1193},  // 29 марта 03:00
  {h:7,    v:1417},  // 29 марта 05:00
  {h:12,   v:1828},  // 29 марта 10:00
  {h:16.97,v:2870}   // 29 марта 14:58
];
```

`h` — часы от 22:00 28 марта. Ось Y до 3000. Цвет `#a83a2c`.

Дополнительный слой (сейчас не показан, можно добавить): доля детей — 468 из 1 193 (39 %) в 03:00, 623 из 1 417 (44 %) в 05:00. Рост доли означает, что ночью вывозили семьями целиком.

**Где править:** функция с `id="chartB"`, переменная `P`.

Эти графики были разработаны, но на постер не попали из-за места. Данные проверены — если освободится место, вставляй.

### Расходы воды, м³/с

Горизонтальные полосы, максимум 1 700.

| Показатель | Значение | Источник |
|---|---|---|
| Обычный весенний санитарный попуск | 50 | Диапазон 21.03.2025 |
| Сброс к 3 апреля (уже снижен) | 500 | МВРИ / Kazakhstan Today |
| **Аварийный сброс 28 марта** | **1 000** | правительство РК 29.03.2024 |
| Пиковый приток *(свидетельство оператора)* | 1 700 | Ш. Абдиев, не гидрограф |

**Что показывает:** сброс был в 20 раз выше обычного и при этом вдвое ниже притока. Разница между 1 700 на входе и 1 000 на выходе — это и есть вода, накапливавшаяся сверх проектной мощности.

> Не добавлять столбец «максимальная пропускная способность» — см. [01-research.md](01-research.md), раздел 5.

### Объёмы воды, млн м³

Горизонтальные полосы, максимум 540, пунктир на отметке 245 (проектная ёмкость).

| Показатель | Значение |
|---|---|
| Проектная ёмкость | 245 |
| Приток 27–29 марта | 200 |
| Сброшено 27.03 – 02.04 | 246 |

### Снегозапас, % от нормы

Две полосы. Максимум 140.

| Год | Значение | Что было |
|---|---|---|
| 2023 | 130 % | паводка не было |

**Что показывает:** снега было меньше, чем годом раньше. Значит причина не в объёме, а в скорости таяния. Убивает отговорку «небывалая стихия».

## Правила оформления графиков

Взяты из методики визуализации данных, проверены на различимость при дальтонизме и в чёрно-белой печати.

- **Палитра.** Синий `#2a78d6`, оранжевый `#eb6834`, зелёный `#1baf7a`, красный `#e34948`. На постере используются приглушённые варианты `#14607d` и `#a83a2c`, согласованные с общей палитрой.
- **Одна ось.** Никогда не делать график с двумя шкалами Y. Две величины разного масштаба — два графика.
- **Цвет по сущности, а не по рангу.** Фильтр, меняющий число рядов, не должен перекрашивать оставшиеся.
- **Тонкие штрихи.** Линии 2 px, точки от 8 px, сетка бледная и отступает на второй план.
- **Подписи значений прямо на графике,** а не только на оси. Но не на каждой точке — только там, где значение важно.
- **Текст графика — цветом текста,** а не цветом ряда. Идентичность несёт метка рядом, а не окраска цифр.
- **Проверка в оттенках серого.** Переведи макет в grayscale: если графики всё ещё различимы — цвет выбран верно.

## Как добавить новый график

1. Поставь в HTML пустой контейнер с координатами:
   ```html
   <div id="chartX" style="left:20mm;top:600mm;width:170mm;height:68mm"></div>
   ```
2. В `<script>` внизу файла добавь блок по образцу `chartB` — он рисует inline SVG с `viewBox` в миллиметрах.
3. Пересобери PDF: `powershell -ExecutionPolicy Bypass -File poster\make-pdf.ps1`

Весь SVG остаётся векторным в PDF, поэтому графики печатаются идеально резко при любом размере.
